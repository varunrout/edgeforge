# EdgeForge: Football Sportsbook Pricing Engine

You are the implementing engineer. A separate lead (Claude in Cowork) owns the plan, audits every phase gate and can veto results. The owner is Varun Rout.

## Source of truth (highest wins)

1. `docs/DECISIONS.md`: locked decisions. These override the brief.
2. `docs/PLAN.md`: phases, deliverables and gate criteria.
3. `docs/BRIEF.md`: the original brief. Use it for intent and quality bar; where it conflicts with 1 or 2, it loses.

Key overrides at a glance: **football only** (no NBA), **no Go component**, **two-week timebox**, **the project is framed as the lifecycle of a football price across three information states: opening (pre-lineup), confirmed lineups, and in-play** (D-015), **you stop at each phase gate** (the brief's "never stop" instruction is overridden).

## How to work

- Work one phase at a time, in the order in `docs/PLAN.md`. Inside a phase, be autonomous: investigate options, choose, implement, log the decision.
- At the end of each phase: run the gate checks, append a section to `docs/GATES.md` (what was built, gate criteria with pass/fail and the command that proves each, open issues, deviations from plan), commit, then **stop** and tell Varun the phase is ready for audit. Do not start the next phase until the lead has passed the gate.
- New decisions go in `docs/DECISIONS.md` using the existing format (ID, decision, why, rejected alternatives, status). Never edit a locked decision; supersede it with a new entry.
- Only stop mid-phase for a genuine blocker (credential, licence question, data source dead). Say exactly what is blocked and what you tried.

## Evidence rule (non-negotiable)

- Never invent, estimate or round-up any result. Every number that appears in README, reports, app copy or the evidence pack must be read from a file in `artifacts/metrics/` produced by code.
- Every metrics JSON carries provenance: `git_sha`, `data_version`, `command`, `config_hash`, `created_at`, `seed`.
- Docs that contain numbers are rendered from metrics by `edgeforge docs render`; CI fails if a rendered number does not match its source.
- Every experiment, including rejected ones, is appended to `experiments/registry.jsonl` with: dataset version, feature set, model, hyperparameters, validation window, metrics, calibration, notes, status (`promoted` / `rejected` / `baseline`).
- Negative results are kept and reported. Never tune against the test window.

## Temporal integrity

- Every price is tagged with an information state: `opening` (T-48h, no lineups), `lineups` (T-60min, confirmed XI and bench), or `inplay` (match minute m, with score and dismissals up to m). Features may only use information available in that state.
- Every feature row has `asof_ts`. Features may only use matches with kickoff strictly before `asof_ts`.
- Validation is walk-forward (rolling origin) by date. Random splits are forbidden.
- Leakage tests are mandatory (see PLAN Phase 2).

## Engineering conventions

- Python 3.12, `uv` for env and lockfile. `ruff` (lint + format), `mypy` on `src/`, `pytest`.
- Package `src/edgeforge/`. Single cross-platform CLI via `typer`: `uv run edgeforge <command>`. No Makefile (owner is on Windows).
- `pathlib` everywhere, no hard-coded paths, all paths from `configs/*.yaml`. Seeds from config.
- Storage: Parquet files + DuckDB (`data/warehouse.duckdb`). SQL for point-in-time feature joins.
- Core libs: numpy, scipy, pandas, duckdb, statsmodels, scikit-learn, pydantic v2, fastapi, streamlit, matplotlib/plotly. Add others only with a logged reason.
- `data/` and `artifacts/sims/` are git-ignored. Raw scraped data is never committed. CI uses synthetic fixtures generated by code.
- Logging via `logging` with a single configured format. No prints in library code.
- Small commits with clear messages. Initialise git if absent. Never push or create remotes without Varun's say-so.
- No secrets in the repo. `.env.example` lists any variables needed.

## Forbidden

NBA or any second sport, Go, Postgres/Supabase, MLflow server, Kafka, Kubernetes, microservices, deep learning, LLM features, fake live betting, fake customers, claims of commercial deployment. Do not create markdown files beyond: README.md, CLAUDE.md, docs/BRIEF.md, docs/PLAN.md, docs/DECISIONS.md, docs/DATA.md, docs/GATES.md, reports/technical_report.md, reports/evidence_pack.md, reports/cv_project_summary.md.
